## Summary

This solution predicts household consumption expenditure (`cons_ppp17`) and derives poverty rates across 19 PPP17 thresholds for multiple survey datasets. The competition metric is a **weighted MAPE on poverty rates**, with heavy emphasis on the 40th percentile threshold (~$8.40/day).

The pipeline combines:
- Per-capita feature engineering (+27% correlation boost over raw features)
- A 4-model gradient boosting ensemble (LightGBM ×2, XGBoost, CatBoost)
- Test-Time Augmentation (TTA) over ±3% utility expense perturbations
- P40-focused survey matching against training surveys
- Per-survey calibration via differential evolution optimization

## How to Run

The entire pipeline runs as a single script with no additional arguments:

```bash
python solution.py
```

### What it does, in order:

1. **Load & merge data** — joins features with ground truth on `survey_id` + `hhid`
2. **Feature engineering** — creates per-capita, consumption diversity, infrastructure, and demographic features
3. **Train ensemble** — GroupKFold (split by survey) trains LightGBM (log), LightGBM (raw), XGBoost (log), CatBoost (log)
4. **Save model weights** — all 20 models + encoders + metadata saved to `saved_models/`
5. **Test-Time Augmentation** — runs 3 inference passes (original, −3%, +3% utility expense) and averages
6. **Survey matching** — matches each test survey to the most similar training survey (60% P40 / 40% mean weighting)
7. **Calibration** — differential evolution optimizes a 3-parameter (scale, shift, gamma) transformation per survey
8. **Output** — writes submission files

### Measured Runtime

Tested on Kaggle default CPU (Intel Xeon @ 2.20GHz, 4 cores, 31GB RAM, no GPU):

| Stage | Actual Time |
|---|---|
| Feature engineering | ~1 min |
| Model training (4 models × 5 folds) | ~24 min |
| TTA inference + calibration | ~3 min |
| **Full pipeline (solution.py)** | **~28 min** |
| **Inference only (predict.py)** | **~3 min** |

## Inference on New Data (No Retraining)

Once `solution.py` has been run (or weights restored from the Kaggle dataset), generate predictions on any new data without retraining:

```bash
python predict.py --test new_test_features.csv --output my_submission.zip
```

### Arguments

| Argument | Default | Description |
|---|---|---|
| `--test` | auto-detected | Path to new test household features CSV |
| `--output` | `submission.zip` | Output zip filename |
| `--models_dir` | `saved_models` | Path to the saved_models/ directory |
| `--weights` | *(none)* | CSV with `survey_id, hhid, weight` columns. Equal weights assumed if omitted. |

> **Notebook users:** `predict.py` is fully compatible with Kaggle and Colab notebooks. It auto-detects the notebook environment and handles argument parsing safely without crashing on Jupyter's sys.argv.

### How it works

`predict.py` loads all saved model weights and metadata, applies identical feature engineering and label encoding as training, runs TTA inference, then applies calibration. For surveys seen during training, the saved scale/shift/gamma parameters are applied directly. For brand-new surveys not seen during training, a fresh survey matching and differential evolution calibration step runs automatically.

## Approach Detail

### Stage 1 — Per-Capita Feature Engineering
Raw features were transformed into per-capita equivalents normalised by household size (`hsize`). Key features: `utl_exp_per_capita` (r=0.66 vs r=0.52 for raw), `consumption_per_capita`, `protein_per_capita`. Zero household sizes are replaced with 1 to prevent division errors. Binary string columns are mapped to {0,1}. Consumption items are grouped into staples, proteins, and luxury categories.

### Stage 2 — 4-Model GroupKFold Ensemble
GroupKFold cross-validation splits by `survey_id` (5 folds). Four models trained per fold:
- LightGBM on log-transformed target (weight: 30%)
- LightGBM on raw target (weight: 20%)
- XGBoost on log-transformed target (weight: 25%)
- CatBoost on log-transformed target (weight: 25%)

### Stage 3 — Test-Time Augmentation (TTA)
Three inference passes are averaged: original features, utility expense −3%, utility expense +3%. All dependent per-capita features are updated accordingly per pass. Reduces noise around poverty line thresholds.

### Stage 4 — P40-Focused Survey Matching & Calibration
Each test survey is matched to the closest training survey using a weighted similarity score (60% P40 similarity, 40% mean similarity). A 3-parameter transformation (scale, shift, gamma power) is then optimised per survey using `scipy.optimize.differential_evolution` to directly minimise the competition's weighted MAPE metric.

## Reproducibility Notes

- All models use fixed random seeds: `seed = 42 + fold_index`
- Differential evolution optimizer uses `seed=42`
- Minor floating-point differences may occur across OS/hardware due to multi-threaded BLAS
- LightGBM early stopping (patience=150) may trigger at slightly different iterations depending on platform

---

## Model Notes & Warnings

- **Minimum 2 training surveys required** for GroupKFold — a `ValueError` is raised otherwise
- Predictions are clipped to `[0.5, 150]` PPP17 dollars
- `hsize=0` households are corrected to `hsize=1` to prevent division errors
- CatBoost and XGBoost do **not** use early stopping in this configuration — re-enable `early_stopping_rounds` if training on much larger datasets
- Differential evolution uses `workers=1` for reproducibility; set `workers=-1` for faster but potentially non-identical results
